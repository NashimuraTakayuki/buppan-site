## 要件① 管理者宛 注文通知メール

### 1-1. 目的
注文発生を管理者(西村さん)がメールでも確実に受け取れるようにする。

### 1-2. トリガー
`submitOrder` の注文確定時(在庫引き当て・購入履歴書き込み成功後)。

### 1-3. 既存通知との関係
既存の管理者LINE通知は**維持**し、メールを**追加**する(併存)。購入者向け確認メール・LINEも現状のまま変更しない。

### 1-4. 宛先の管理方法
既存の「システム設定」シート(設定キー | 値)に以下の行を追加し、西村さんが自分で変更できるようにする。

| 設定キー | 値の例 |
|---|---|
| notification.adminEmails | nishimura@example.com,sub@example.com |

- カンマ区切りで複数宛先に対応する。
- シート編集時は既存の onEdit によるキャッシュ無効化(`SHEET_CACHE_MAP`)が効くため、変更は即時反映される。
- `CONFIG_DEFAULTS` には空文字を定義し、`getConfig()` 内の上書き対象(`ov()`)に `notification.adminEmails` を追加する。

### 1-5. メール内容
既存の管理者LINE通知と同内容とする。

- 件名: `【アスリッシュ物販】新規注文のお知らせ(注文ID: ORD-XXXXXX)`
- 本文: 注文ID/注文日時/氏名/スクール/メールアドレス/注文商品/小計・割引・合計金額(LINE通知の `adminMessage` と同じ組み立て)

### 1-6. エラー処理
- 送信失敗時も注文は成功扱い(既存のメール・LINE通知と同方針)。`writeLog("ERROR", ...)` に記録する。
- 宛先が未設定(空)の場合は送信をスキップし、`writeLog("WARN", ...)` に記録する。

### 1-7. 留意事項(要認識)
- MailAppの送信クォータは無料Googleアカウントで100宛先/日、Workspaceアカウントで1,500宛先/日(Google公式ドキュメントより)。1注文あたり購入者向け+管理者向けの2通消費となるため、無料アカウント運用の場合は約50注文/日が上限の目安。GASがどのアカウントで動いているかを実装時に確認する。

## 要件② 最終支払額の表示(購入履歴シート)

### 2-1. 目的
1回の買い物で最終的に支払う金額を、購入履歴シート上で一目でわかるようにする。

### 2-2. 列の追加(案B)
- 「購入履歴」シートの「支払金額小計」と「ステータス」の間に新列「**最終支払額**」を挿入する。
- 値は**注文の先頭行(最初の商品行)のみ**に記入する。値 = 商品小計合計 − タイムセール割引 − 会員特典割引(コード上の `finalTotalAmount`)。
- 割引行・2品目以降の行のこの列は空欄とする。
- これにより「最終支払額」列を縦にSUMするとそのまま総売上になる(二重計上が起きない)。

### 2-3. 書式
- 「最終支払額」列に背景色(薄いオレンジ系)を設定し、金額セルは太字にする。
- 列挿入・書式設定は移行スクリプト(2-5)で行い、新規注文の書き込み時にもセル書式を適用する。

### 2-4. 割引行のグループ化
- 1注文が複数行になる場合(タイムセール割引行・会員特典割引行・2品目以降)、**先頭行を除く明細行**を行グループ化する。
- 記録直後のデフォルトは**折りたたんだ状態**とする(普段は注文単位のスッキリした一覧。内訳は「+」で展開)。
- 実装: 注文書き込み直後に `shiftRowGroupDepth(1)` を適用し、グループを collapse する。

### 2-5. ステータスの記入方式(変更)
- ステータス(未入金/入金済)は**注文の先頭行のみ**に記入し、割引行・2品目以降の明細行は**空欄**とする。
- 折りたたんだ状態でもステータスが常に見え、隠れた行に古いステータスが残る問題を構造的に排除する。
- 新規注文の書き込み時、`submitOrder` は先頭行にのみ「未入金」を設定する。
- 入金管理の運用は「注文先頭行のステータスを変更する」のみとなる(展開不要)。
- 補足: 現行コードにステータス列を読む処理は存在しないため、空欄化による機能影響はない。

### 2-6. 過去注文への遡及反映
既存の全注文に対して、一括移行スクリプト(GAS関数、手動1回実行)で以下を行う。

1. 実行前に「購入履歴」シートのバックアップ(シートコピー)を作成する。
2. 「最終支払額」列を挿入し、ヘッダーを更新する(既存のヘッダー自動更新ロジックとの整合を取るため、コード側の `historyHeaders` も同時に更新してからデプロイする)。
3. 注文IDごとに「支払金額小計」を集計し、先頭行に最終支払額を記入する。
4. 注文IDごとに、先頭行以外のステータスをクリアする(2-5の方式へ統一)。同一注文内でステータスが食い違っていた場合は**先頭行の値を正**として残し、食い違いの内容をログに出力して手動確認に回す。
5. 注文IDごとに先頭行以外をグループ化し、折りたたむ。
6. 検証: 「最終支払額」列の合計 = 「支払金額小計」列の合計 が一致することを確認する。

## 導入後の確認事項(検証チェックリスト)

### ①通知メールの確認

- [ ] テスト注文を1件実施し、システム設定シートに登録した**全宛先**に管理者メールが届く
- [ ] メールの件名・本文(注文ID/日時/氏名/スクール/メール/商品/金額)が注文内容と一致している
- [ ] 既存の管理者LINE通知も従来どおり届く(併存の確認)
- [ ] 購入者向けの確認メール・LINE通知も従来どおり届く(デグレ確認)
- [ ] 設定シートで宛先を変更した直後の注文で、新しい宛先に届く(キャッシュ即時反映の確認)
- [ ] 宛先を空にして注文しても注文自体は成功し、ログシートにWARNが記録される

### ②金額表示の確認(新規注文)

- [ ] 割引あり注文(タイムセール+会員特典+複数商品)で、**先頭行のみ**に最終支払額が記入される
- [ ] 最終支払額 = 支払金額小計の合計(商品−割引)と一致する
- [ ] 最終支払額セルに背景色+太字の書式が付いている
- [ ] 明細行(割引行・2品目以降)がグループ化され、**折りたたまれた状態**で記録される
- [ ] ステータスは先頭行のみ「未入金」、明細行は空欄になっている
- [ ] 割引なし・1商品のみの注文でも正常に記録される

### ②金額表示の確認(過去分の移行後)

- [ ] バックアップシートが作成されている
- [ ] 「最終支払額」列のSUM = 「支払金額小計」列のSUM が一致する
- [ ] 過去注文の明細行がグループ化・折りたたみされている
- [ ] 過去注文の明細行のステータスがクリアされ、先頭行のみに残っている
- [ ] ステータス食い違いのログを確認し、該当注文を手動で確認済み

### 運用確認(西村さんへの引き継ぎ)

- [ ] 宛先メールアドレスの設定・変更方法を西村さんに共有した
- [ ] 「+/−」での明細の開閉方法を共有した
- [ ] 入金チェックは「注文先頭行のステータスのみ変更すればよい」ことを共有した
- [ ] 導入後数日間、ログシートのERROR/WARNを監視し異常がないことを確認した

## 確定済み合意事項(経緯)

1. 成果物: 改善方針ドキュメント → そのまま実装まで実施(記載粒度: 実装内容まで)
2. ②は案B(合計列方式)+行グループ化(デフォルト折りたたみ)で確定
3. 過去注文にも遡及反映する
4. ①はLINE通知併存・宛先はシート管理・内容はLINE通知と同内容
5. ③読み込み高速化は保留
6. ステータスは注文先頭行のみ記入(自動同期案は廃止)。移行時に明細行のステータスをクリアする
